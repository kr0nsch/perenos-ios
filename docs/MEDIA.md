# Скриншоты и демонстрации «Переноса»

В README и на сайте используются **реальные кадры интерфейса приложения в деморежиме**.
Телефоны, аккаунт и приложения в нём вымышлены. Демонстрации объясняют последовательность
действий и не измеряют скорость переноса на настоящих устройствах.

## Подготовить приложение

Используйте портативную сборку нужного релиза или отдельную опубликованную сборку
из исходников. Для съёмки сохраните `portable.txt` рядом с `Perenos.exe`: настройки
этой копии будут находиться в её папке `Data`, отдельно от установленного приложения.
Не подменяйте настройки рабочей копии и не входите в настоящий Apple Account.

Перед запуском закройте **только свою демонстрационную копию** и задайте
`Data/settings.json`:

```json
{
  "Language": "ru-RU",
  "Theme": "Light"
}
```

Варианты языка: `ru-RU`, `en-US`. Варианты темы: `Light`, `Dark`. Четыре серии
сохраняются в `docs/screenshots/ru-light`, `ru-dark`, `en-light`, `en-dark`.
Снимайте все экраны одной серии при одинаковом размере окна и масштабе Windows.
В кадре должно быть только окно приложения целиком, включая название и кнопки.

```powershell
# Демо с пустой библиотекой: перенос сейчас и сохранение
.\Perenos.exe --demo

# Демо с подготовленной библиотекой: установка сохранённых приложений
.\Perenos.exe --demo-saved
```

Демо самостоятельно создаёт вымышленные телефоны и приложения. Устройства появляются
через несколько секунд. Во время запроса доверия дождитесь готовности нового телефона.
Для экрана входа используйте `anna@example.com`, вымышленный пароль и код `123456`.
Деморежим принимает их локально и не отправляет Apple.

Библиотека деморежима пересоздаётся при каждом запуске в `%TEMP%\AppBridgeDemo`.
Это историческое внутреннее имя. Не запускайте несколько демонстрационных копий
одновременно: они используют одну временную библиотеку.

В серии 1.2.0 для переноса сейчас и сохранения выбраны три бесплатных приложения:
`Bloom Journal`, `Cloudy` и `Daily Planner`. Сохранение снято после переноса в той же
демосессии: отметки «Уже сохранено» показывают повторное сохранение существующих файлов.
Для установки из библиотеки приложение запущено заново с `--demo-saved`: в библиотеке
11 приложений, автоматически выбраны 9 совместимых, вход в аккаунт не выполняется.
Повторяйте эту последовательность для каждого языка и темы, чтобы серии были сопоставимы.

Для демонстрации ошибки
можно отдельно выбрать `Grand Chess`: деморежим специально показывает отказ от покупки
платного приложения. Не выдавайте этот учебный сценарий за результат реального переноса.

Проверьте каждый PNG: правильное название и язык, загруженные иконки, отсутствие
случайного меню, системных окон, частично отрисованных переходов или обрезанных элементов.
Не заменяйте старый логотип поверх старого кадра: заново снимайте актуальное приложение.

Если средство захвата возвращает JPEG, сохраняйте исходные байты с расширением `.jpg`
в `artifacts/captures-<версия>/<язык>-<тема>/`, например
`artifacts/captures-1.2.0/ru-light/1-connect.jpg`. Не называйте JPEG-файл `.png`.
Если средство захвата уже вернуло настоящий PNG, оставьте расширение `.png`:
генератор принимает оба формата и предпочитает `.jpg`, если присутствуют оба файла.
Когда сняты все 16 экранов каждой из четырёх серий, проверьте и нормализуйте их:

```powershell
python build/generate-demo-media.py --capture-root artifacts/captures-1.2.0 --check
python build/generate-demo-media.py --capture-root artifacts/captures-1.2.0 --normalize-only
```

Нормализация декодирует JPEG и сохраняет настоящий PNG, не меняя размеры или пиксели
декодированного изображения. Она не повышает качество исходного JPEG и не ретуширует
интерфейс. Исходные `.jpg` остаются нетронутыми. Перед записью проверяется полный набор
кадров и единый размер окна; после записи проверяется совпадение пикселей. Параметры
`--languages ru` или `--themes light` позволяют обработать только указанную полную серию.

## Собрать GIF

Нужны Python 3.11+ и Pillow. Если локальное окружение проекта уже настроено,
используйте `.venv/Scripts/python.exe`; иначе установите Pillow в отдельное окружение.

```powershell
python -m pip install Pillow
python build/generate-demo-media.py --check
python build/generate-demo-media.py
```

Можно выполнить нормализацию и сборку GIF одной командой:

```powershell
python build/generate-demo-media.py --capture-root artifacts/captures-1.2.0
```

По умолчанию создаются восемь GIF: `demo-{ru,en}-{light,dark}.gif` и
`later-{ru,en}-{light,dark}.gif`. Чтобы дополнительно собрать сценарий сохранения:

```powershell
python build/generate-demo-media.py --flows demo later save
```

Кадры пропорционально уменьшаются до ширины 900 пикселей и никогда не увеличиваются.
Размер можно изменить параметром `--width`. Удержания по 2,5–4,5 секунды позволяют
прочитать интерфейс. Скрипт не дорисовывает UI, курсор или переходы. Единая палитра
уменьшает изменение цветов между кадрами; PNG остаются исходниками без потерь.

Рядом с каждым GIF создаётся JSON с порядком кадров, длительностями, размерами и
SHA-256 исходных PNG и результата. Эти файлы позволяют проверить, из каких снимков
собрана демонстрация. Скрипт отклоняет неполные серии и несовпадающие размеры кадров.

Для проверки генератора без изменения опубликованных файлов:

```powershell
python build/generate-demo-media.py --output-dir artifacts/media-check
```

После обновления просмотрите GIF целиком, проверьте обе темы и оба языка, обновите
номер версии в подписях README и на сайте и проверьте ссылки на исходные скриншоты.
Сайт должен предлагать статичный кадр при отключённой анимации или предпочтении
`prefers-reduced-motion`, а воспроизведение демонстрации — по действию посетителя.
