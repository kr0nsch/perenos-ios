# Скриншоты и демонстрации «Переноса»

В README и на сайте используются **реальные кадры интерфейса приложения в деморежиме**.
Телефоны, аккаунт и приложения в нём вымышлены. Демонстрации объясняют последовательность
действий и не измеряют скорость переноса на настоящих устройствах.

Скриншоты снимаются непосредственно с окна в PNG без потерь. GIF собираются из
непрерывной записи: в них сохраняются переходы, появление элементов и движение
индикаторов. Системный курсор не захватывается, а курсор и подсветка кликов при
обработке не дорисовываются.

## Подготовить приложение

Используйте портативную сборку нужного релиза или отдельную опубликованную сборку
из исходников. Для съёмки сохраните `portable.txt` рядом с `Perenos.exe`: настройки
этой копии будут находиться в её папке `Data`, отдельно от установленного приложения.
Не подменяйте настройки рабочей копии и не входите в настоящий Apple Account.

Запоминайте PID запущенной вами копии. Перед новым запуском закройте **только эту
демонстрационную копию по её PID** и задайте
`Data/settings.json`:

```json
{
  "Language": "ru-RU",
  "Theme": "Light"
}
```

Варианты языка: `ru-RU`, `en-US`. Варианты темы: `Light`, `Dark`. Четыре серии
сохраняются в `docs/screenshots/ru-light`, `ru-dark`, `en-light`, `en-dark`.
Снимайте все экраны одной серии при одинаковом размере окна и масштабе Windows.
В кадре должно быть только окно приложения целиком, включая название и кнопки.

```powershell
# Демо с пустой библиотекой: перенос сейчас и сохранение
.\Perenos.exe --demo

# Демо с подготовленной библиотекой: установка сохранённых приложений
.\Perenos.exe --demo-saved
```

Демо самостоятельно создаёт вымышленные телефоны и приложения. Устройства появляются
через несколько секунд. Во время запроса доверия дождитесь готовности нового телефона.
Снимите форму входа с пустыми полями или только с вымышленным адресом. Для продолжения сценария используйте
`anna@example.com`, вымышленный пароль и код `123456`.
Деморежим принимает их локально и не отправляет Apple.

Библиотека деморежима пересоздаётся при каждом запуске в `%TEMP%\AppBridgeDemo`.
Это историческое внутреннее имя. Не запускайте несколько демонстрационных копий
одновременно: они используют одну временную библиотеку.

| | `4-sign-in.png` | Форма входа с пустыми полями или вымышленным адресом, без настоящих секретов |
| | `5-ready.png` | Сводка перед установкой |

| | `later-4-saved.png` | Библиотека с версиями и совместимостью |

| | `save-2-ready.png` | Сводка перед скачиванием |
| | `save-3-done.png` | Итог сохранения на компьютер |

В серии 1.2.0 для переноса сейчас и сохранения выбраны три бесплатных приложения:
`Bloom Journal`, `Cloudy` и `Daily Planner`. Сохранение снято после переноса в той же
демосессии: отметки «Уже сохранено» показывают повторное сохранение существующих файлов.
Для установки из библиотеки приложение запущено заново с `--demo-saved`: в библиотеке
11 приложений, автоматически выбраны 9 совместимых, вход в аккаунт не выполняется.
Повторяйте эту последовательность для каждого языка и темы, чтобы серии были сопоставимы.

Для демонстрации ошибки
можно отдельно выбрать `Grand Chess`: деморежим специально показывает отказ от покупки
платного приложения. Не выдавайте этот учебный сценарий за результат реального переноса.

Проверьте каждый PNG: правильное название и язык, загруженные иконки, отсутствие
случайного меню, системных окон, частично отрисованных переходов или обрезанных элементов.
Не заменяйте старый логотип поверх старого кадра: заново снимайте актуальное приложение.

## Записать окно без курсора

Используйте [Record-DemoWindow.ps1](../build/Record-DemoWindow.ps1) на Windows.
Передайте точный PID уже запущенного демоприложения и новую папку внутри `artifacts`.
Скрипт принимает только `Perenos.exe` или прежний `AppBridge.exe`, запущенный с
`--demo` либо `--demo-saved`, и проверяет наличие `portable.txt` рядом с программой.
Он не запускает приложение, не нажимает кнопки, не меняет размер окна и не закрывает
процесс. Управляйте своей демонстрационной копией отдельно, оставляя запись включённой.

```powershell
# Вместо 1234 укажите PID своей изолированной демо-копии.
powershell -NoProfile -ExecutionPolicy Bypass -File build/Record-DemoWindow.ps1 `
  -ProcessId 1234 -OutDir artifacts/recordings-1.2.0/ru-light/demo `
  -IntervalMs 90 -MaxSeconds 600
```

Команда записывает окно до появления файла `stop` или истечения `MaxSeconds`.
Если приложение закроется во время съёмки, запись завершится с ошибкой; сначала
остановите рекордер. Чтобы остановить запись из другого терминала:

```powershell
New-Item -ItemType File -Path artifacts/recordings-1.2.0/ru-light/demo/stop
```

Демоприложение после этого остаётся открытым. Не используйте массовое завершение
процессов по имени: у пользователя может работать другая копия. Запись не перезаписывает
существующую папку с файлами и не разрешает пути через ссылки за пределами `artifacts`.
`-ExecutionPolicy Bypass` в примере относится только к дочернему процессу PowerShell;
системная политика выполнения не меняется. Если запуск локальных скриптов уже разрешён,
этот параметр можно убрать.

Захват выполняется через `PrintWindow` с флагом `PW_RENDERFULLCONTENT` (`2`). Границы
видимого окна берутся у DWM: системная тень и невидимые поля не попадают в кадр,
заголовок и элементы управления сохраняются. Курсор Windows не входит в изображение
окна; скрывать его в настройках системы или стирать с готового кадра не требуется.
Не сворачивайте и не изменяйте размеры приложения во время записи.

В каждой папке записи находятся:

| Файл | Содержимое |
|---|---|
| `f00000.png`, `f00001.png`, … | Последовательные исходные кадры PNG без потерь |
| `frames.csv` | Номер каждого кадра и время захвата в миллисекундах UTC |
| `window.txt` | Координаты и размеры видимых границ окна |
| `capture.json` | Способ захвата, размеры, число кадров, время, причина остановки и SHA-256 исполняемого файла |

После остановки дождитесь завершения команды и проверьте `"status": "complete"`
в `capture.json`. Сборка принимает только завершённые записи: `recording`, `failed`
или отсутствующий манифест отклоняются. Не изменяйте исходные PNG и метаданные записи
во время сборки.

Для каждого языка и темы снимите перенос сейчас в `demo`, а установку сохранённых
приложений — в `later`. Перед `later` перезапустите **свою** копию с `--demo-saved`,
чтобы восстановить библиотеку из 11 приложений. Отдельно снимите сценарий сохранения
в папку `save` для трёх статичных кадров `save-*`.

Для галереи выберите из записей 16 полностью отрисованных кадров и укажите их время
в `timeline.json`, как описано ниже. Генератор сохранит их под именами из таблицы
в `docs/screenshots/<язык>-<тема>/`. Проверяйте выбранные PNG до сборки;
для `6-installing.png` нужна выполняющаяся установка, а не итоговый экран.
Размер каждого кадра должен совпадать с исходной записью. Все четыре серии дают
**64 PNG**. Для отдельного статичного снимка можно сделать короткую запись с
`-MaxSeconds 1` и выбрать стабильный кадр из неё.

JPEG в этом процессе не используется. Конвертация JPEG в PNG не возвращает потерянные
детали текста, а удаление курсора с готового изображения может повредить интерфейс.
При ошибке захвата переснимите окно. Не заменяйте непрерывную запись набором статичных
экранов: такой GIF теряет движение интерфейса даже при большем разрешении.

## Выбрать фрагменты и статичные кадры

Рядом с `frames.csv` каждой записи создайте `timeline.json`. Время задаётся абсолютными
миллисекундами UTC из `frames.csv`, а не номерами кадров. Выберите начало и конец
действия, уберите ожидание между действиями и оставьте достаточно времени для чтения.
Внутри выбранных фрагментов используются последовательные кадры записи, включая
анимации самого приложения.

Пример структуры для `ru-light/demo/timeline.json` — все времена в нём нужно заменить
значениями своей записи:

```json
{
  "schema_version": 1,
  "version": "1.2.0",
  "language": "ru",
  "theme": "light",
  "flow": "demo",
  "segments": [
    {
      "start_ms": 1793700000000,
      "end_ms": 1793700010000
    },
    {
      "start_ms": 1793700010000,
      "end_ms": 1793700040000,
      "output_duration_ms": 20000
    }
  ],
  "stills": {
    "1-connect.png": 1793700001000,
    "2-choose-apps.png": 1793700008000,
    "3-target.png": 1793700013000,
    "4-sign-in.png": 1793700018000,
    "5-ready.png": 1793700026000,
    "6-installing.png": 1793700030000,
    "7-done.png": 1793700039000
  }
}
```

Без `output_duration_ms` фрагмент сохраняет исходную длительность. С этим параметром
его воспроизведение ускоряется или замедляется: например, 30 секунд записи можно
показать за 20 секунд. Ретайминг нужен для читаемого темпа и коротких ожиданий; такой
ролик не служит замером производительности. Не ускоряйте переходы так, чтобы они
пропадали между кадрами.

Фрагменты должны идти по времени, не пересекаться и находиться в пределах записи.
`stills` задаёт семь статичных кадров для `demo`, шесть для `later` и три для `save`
по именам из таблицы выше. Для `save`, используемого только в галерее, можно оставить
`"segments": []`. Сначала просмотрите выбранные исходные кадры, затем передайте
`timeline.json` генератору: он сохранит PNG в `docs/screenshots` без изменения пикселей.
Если время находится между двумя кадрами, выбирается последний кадр не позже
указанного времени; для точного выбора используйте его отметку из `frames.csv`.

## Собрать GIF

Нужны Python 3.11+, Pillow и FFmpeg, доступный в `PATH` или через `--ffmpeg <путь>`.
Если окружение проекта уже
настроено, используйте `.venv/Scripts/python.exe`; иначе установите Pillow в отдельное
окружение. Исходные записи и промежуточные результаты храните в игнорируемой папке
`artifacts`, а не в `docs`.

```powershell
python -m pip install Pillow
ffmpeg -version

# Проверка входных записей, монтажа и выбранных PNG без записи результатов.
python build/generate-demo-media.py --recordings-dir artifacts/recordings-1.2.0 --check
python build/generate-demo-media.py --recordings-dir artifacts/recordings-1.2.0 --flows save --stills-only --check

# Два ролика для каждого из четырёх вариантов языка и темы, плюс статичные кадры.
python build/generate-demo-media.py --recordings-dir artifacts/recordings-1.2.0
python build/generate-demo-media.py --recordings-dir artifacts/recordings-1.2.0 --flows save --stills-only
```

Результат — **8 GIF**: `demo-{ru,en}-{light,dark}.gif` и
`later-{ru,en}-{light,dark}.gif`, а также **64 PNG** в четырёх галереях.
Параметры `--languages ru` и `--themes light` позволяют собрать один полный вариант.
`--flows` выбирает сценарии, `--stills-only` сохраняет только статичные PNG.

FFmpeg пропорционально уменьшает запись фильтром Lanczos до ширины 900 пикселей
(`--width`) и собирает GIF с частотой 12 кадров в секунду (`--fps`). Для всех кадров
ролика вычисляется общая палитра до 256 цветов с `palettegen` в режиме `stats_mode=diff`;
`paletteuse` применяет дизеринг
`sierra2_4a`, чтобы сохранить плавность градиентов. Разрешение не увеличивается
относительно исходника. Курсор, клики, текст и переходы поверх изображения не рисуются.

Генератор принимает только настоящие PNG одного размера, проверяет последовательность
кадров и времени, наличие всех выбранных экранов и границы монтажа. Рядом с каждым GIF
сохраняется JSON-манифест: размеры, число кадров, длительность, параметры кодирования,
SHA-256 результата, монтажа, таблицы времени и набора исходных PNG. В манифесте также
есть выбранные фрагменты, контрольная сумма последовательности кадров на выходе
и происхождение статичных кадров: имя исходного PNG, запрошенное и фактическое время,
SHA-256. Для GIF манифест называется, например, `demo-ru-light.json`, для
`--stills-only` — `save-ru-light-stills.json`. По этим данным можно проверить сборку
и повторить её с сохранёнными записями.

Для пробной сборки, которая не меняет опубликованные файлы:

```powershell
python build/generate-demo-media.py --recordings-dir artifacts/recordings-1.2.0 `
  --languages ru --themes light `
  --screenshots-dir artifacts/media-check/screenshots --output-dir artifacts/media-check/gifs
```

Просмотрите каждый GIF целиком: текст читается, анимации и прогресс движутся плавно,
курсор и его подсветка отсутствуют, переходы и финальный результат не обрезаны.
Проверьте обе темы и оба языка, сравните кадры с исходными PNG. После обновления
проверьте номер версии в подписях README и сайта, галереи и ссылки на них.
При `prefers-reduced-motion` README показывает статичный кадр; на сайте демонстрация
запускается только по действию посетителя, а без JavaScript доступен статичный интерфейс.
