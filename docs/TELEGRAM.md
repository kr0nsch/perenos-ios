## Регламент ведения

1. **Релиз → пост.** После каждого релиза публикуйте changelog-пост: дата, 3–6 пунктов
   простыми словами, ссылка на тег релиза и полный CHANGELOG. Шаблон — функция
   `release_post()` в `scripts/telegram/publish_posts.py`.
2. **Без спама.** Не больше 1–2 постов в неделю вне релизов. Канал официальный:
   только релизы, changelog и гайды.
3. **Честные ограничения.** Не обещать восстановление любой покупки: лицензию проверяет
   Apple, каталог — кандидаты, а не гарантия. macOS-пакеты называть тестовыми, пока
   нет Developer ID и нотаризации. Формулировки брать из README и CHANGELOG.
4. **Медиа только текущей версии.** GIF, видео и скриншоты в постах — из релиза,
   о котором пост (перегенерация при подготовке релиза, как в 1.9.0).
5. **Секреты не публиковать.** Токен бота, IPA пользователей, персональные данные
   и отчёты устройств никогда не попадают в канал и в репозиторий.

## Как опубликовать новые посты

Скрипты лежат в `scripts/telegram/`, нужен Python 3.12+ (стандартная библиотека,
без зависимостей). Токен читается из локального файла «Текстовый документ.txt»
в корне репозитория (добавлен в `.gitignore`) или из переменной `TELEGRAM_BOT_TOKEN`.

```powershell
# добавить запись в POSTS (например, release_post("1.10.0", ...)) и запустить:
python scripts/telegram/publish_posts.py --dry-run   # проверка длины
python scripts/telegram/publish_posts.py             # публикует только новые посты
```

Опубликованные `message_id` хранятся в `scripts/telegram/posts_state.json`,
повторный запуск не создаёт дублей. `--only key1,key2` — точечная публикация,
`--force` — перепубликовать всё (осторожно).

## Обратная связь

Два равноправных пути, оба видны в посте `#обратная_связь`:

1. **Бот @perenos_ios_bot** — для быстрых сообщений. Пользователь нажимает кнопку
   под постом, выбирает тип (🐛 баг, 💡 идея, 💬 отзыв/вопрос) и отправляет текст
   или скриншот. Все действия — кнопками, экран бота редактируется на месте,
   лишние сообщения в личке не накапливаются.
2. **GitHub Issues** — для багов и совместимости: шаблоны `bug_report.yml`,
   `feature_request.yml`, `compatibility_report.yml`. Так проблема не теряется
   и попадает в работу с историей.

### Как работает бот

```powershell
python scripts/telegram/feedback_bot.py            # запуск (long polling)
python scripts/telegram/feedback_bot.py --selftest # проверка логики без сети
```

• Владелец подключается один раз по секретной ссылке `?start=owner_<код>` —
  она печатается в лог `scripts/telegram/feedback_bot.log` при первом запуске,
  пока владелец не зарегистрирован. Обычный `/start` владельцем не делает.
• Сообщения пользователей пересылаются владельцу с кнопками «✍️ Ответить»
  и «✅ Принято». Ответ следующим сообщением уходит пользователю в тот же чат.
• Если владелец ещё не подключён, сообщения сохраняются в очередь и доставляются
  после регистрации или при следующем старте бота. Владелец зарегистрирован
  2026-11-23; его обычный `/start` открывает экран владельца.
• Состояние — `scripts/telegram/feedback_state.json` (в `.gitignore`).
  Сброс владельца и очереди: остановить бота, удалить файл, запустить снова.
• После перезагрузки компьютера бота нужно запустить снова командой выше.
